Section 01

Project Overview

A License Plate Recognition (LPR) system is a computer-vision application that automatically detects and reads vehicle registration numbers from images. This project demonstrates how classical algorithms from the Analysis and Design of Algorithms syllabus — edge detection, contour analysis, and searching — can be combined with modern OCR to build a real-world system.

The system takes a vehicle image as input, runs it through a preprocessing and detection pipeline, extracts the plate text using Tesseract OCR, and finally searches a vehicle registry database to return owner information.

🔍

Image Processing

Grayscale conversion, bilateral filtering, and Canny edge detection prepare the image for analysis.

⬜

Contour Detection

Closed rectangular contours are extracted from the edge map and filtered by aspect ratio to find the plate region.

🔤

OCR Extraction

Tesseract reads alphanumeric characters from the cropped plate image and returns raw text.

🗄️

Database Search

Hash-based dictionary lookup (O(1)) with linear-search fallback for fuzzy matching.

🪟

Visual Output

Four OpenCV windows display the original image, edges, detected plate, and cropped plate.

📊

Complexity Analysis

Each algorithm stage is analysed for time and space complexity for academic evaluation.

Section 02

System Modules

The system is divided into twelve clearly-commented Python modules, each responsible for one stage of the pipeline. This modular design makes the code easy to understand, test, and extend.

  1. Imports & Configuration — Loads OpenCV, NumPy, Pytesseract, and the regular-expression library. Sets the Tesseract executable path for Windows.
  2. Vehicle Database — A Python dictionary keyed by plate number, storing owner name and vehicle type. Demonstrates hash-map data structure usage.
  3. Banner & Utilities — Console formatting helpers that make the terminal output structured and readable.
  4. Image Loading — Reads the image file from disk using cv2.imread() and validates the path and format. Time complexity O(W×H).
  5. Image Preprocessing — Three-step pipeline: grayscale conversion → bilateral filtering → Canny edge detection. Converts the coloured photograph into a clean binary edge map.
  6. Contour Detection & Plate Localisation — Extracts all closed contours from the edge map, sorts by area, and applies a 4-vertex + aspect-ratio filter to isolate the number plate region.
  7. OCR Text Extraction — Upscales the cropped plate, applies Otsu thresholding, then passes it to Tesseract with a whitelist of valid characters.
  8. Text Cleaning — Uses regex to strip all non-alphanumeric characters and convert to uppercase, producing a clean plate string like KA01AB1234.
  9. Database Search — Attempts an exact hash-map lookup (O(1)), then falls back to character-level linear similarity search (O(n)).
  10. Result Display — Prints a structured summary of the recognised plate and owner details to the terminal.
  11. Visual Windows — Opens four cv2.imshow() windows showing the four processing stages side by side.
  12. Demo Mode — Runs three database lookups without needing a real image, useful for academic demonstration.

Section 04

Algorithms Used

Each stage of the pipeline employs a specific algorithm from computer science. Below is a detailed explanation of each.

1. Canny Edge Detection Algorithm

Proposed by John F. Canny in 1986, this is the most widely used edge-detection algorithm due to its ability to produce thin, well-connected edges while suppressing noise.

Algorithm Steps

Step 1 — Gaussian Smoothing: Convolve the grayscale image with a Gaussian kernel to suppress high-frequency noise.
Step 2 — Gradient Computation: Apply Sobel filters in X and Y directions to compute gradient magnitude and direction at each pixel.
Step 3 — Non-Maximum Suppression: Thin the edges by keeping only the local maxima of the gradient magnitude along the gradient direction.
Step 4 — Double Thresholding: Classify pixels as strong edges (above high threshold), weak edges (between thresholds), or non-edges (below low threshold).
Step 5 — Edge Tracking by Hysteresis: Retain weak edges only if they are connected (8-connectivity) to at least one strong edge pixel.

Time Complexity: O(W × H) Space Complexity: O(W × H)

2. Contour Detection Algorithm

OpenCV's findContours() implements the Suzuki-Abe algorithm (1985), which traces the boundaries of binary regions in a raster image. After extraction, contours are sorted by area and each is approximated using the Ramer–Douglas–Peucker algorithm via approxPolyDP().

Plate Filtering Heuristics

A contour is accepted as a candidate plate if its polygon approximation has exactly 4 vertices (quadrilateral), its bounding rectangle has an aspect ratio between 1.5 and 6.0 (typical for number plates), its width exceeds 80 px, and its height exceeds 20 px.

Contour Extraction: O(W × H) Sorting: O(n log n) Polygon Approximation: O(n) per contour

3. Bilateral Filtering

A non-linear, edge-preserving smoothing filter. Unlike Gaussian blur which blurs edges, bilateral filtering weights each pixel by both spatial proximity and radiometric similarity, preserving sharp boundaries while removing noise in flat regions.

Parameters Used

d=11 (neighbourhood diameter), sigmaColor=17, sigmaSpace=17. Higher sigma values produce stronger smoothing.

Time Complexity: O(W × H × d²)

4. OCR — Optical Character Recognition

Tesseract OCR v4+ uses an LSTM (Long Short-Term Memory) neural network trained on multi-language character images. The input image is binarised using Otsu's threshold before OCR, which maximises inter-class variance between dark text and bright background.

Configuration Used

--psm 8 (single word mode), --oem 3 (LSTM engine), character whitelist restricted to A–Z and 0–9 to prevent false characters.

Time Complexity: O(n) — linear in number of characters

5. Database Search — Hash Map Lookup

Python's built-in dict is a hash table. Lookup is performed by hashing the key string, computing a table index, and directly accessing the bucket — no traversal needed in the average case. A fallback linear-similarity search counts matching characters at each position and accepts candidates with ≥ 80% similarity.

Search Strategy

Primary: Exact hash-map lookup — plate_number in VEHICLE_DATABASE.
Fallback: Linear scan with character-level similarity score for partial OCR matches.

Exact Lookup: O(1) average, O(n) worst case Similarity Search: O(n × k) — n entries, k characters each

Annotated Source Code

Preprocessing Pipeline

python — preprocess_image()
def preprocess_image(image):
    # Step 1: Convert BGR to Grayscale
    # Formula: Gray = 0.114·B + 0.587·G + 0.299·R
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

    # Step 2: Bilateral Filter — removes noise, keeps edges
    # d=11 neighbourhood; sigmaColor=17; sigmaSpace=17
    filtered = cv2.bilateralFilter(gray, d=11,
                  sigmaColor=17, sigmaSpace=17)

    # Step 3: Canny Edge Detection
    # Pixels > 200  → strong edges (kept)
    # Pixels 30–200 → weak edges (kept if near strong)
    # Pixels < 30   → discarded
    edges = cv2.Canny(filtered,
                threshold1=30, threshold2=200)

    return gray, filtered, edges

Contour-Based Plate Detection

python — detect_number_plate()
# Find all contours in the binary edge map
contours, _ = cv2.findContours(
    edges.copy(), cv2.RETR_TREE, cv2.CHAIN_APPROX_SIMPLE
)

# Sort by area, largest first; analyse top 30
contours = sorted(contours,
    key=cv2.contourArea, reverse=True)[:30]

for contour in contours:
    perimeter = cv2.arcLength(contour, True)
    approx    = cv2.approxPolyDP(contour,
                    0.018 * perimeter, True)

    if len(approx) == 4:          # Must be a quadrilateral
        x, y, w, h = cv2.boundingRect(approx)
        aspect_ratio = w / float(h)

        if 1.5 <= aspect_ratio <= 6.0:  # Plate shape check
            plate_image = image[y:y+h, x:x+w]  # Crop the plate
            break

OCR with Tesseract

python — extract_text_ocr()
# Upscale 2× for better OCR resolution
plate_large  = cv2.resize(plate_image, None,
               fx=2, fy=2, interpolation=cv2.INTER_CUBIC)

# Convert to grayscale, then Otsu threshold
plate_gray   = cv2.cvtColor(plate_large, cv2.COLOR_BGR2GRAY)
_, plate_thresh = cv2.threshold(
    plate_gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU
)

# Tesseract: single word mode, LSTM engine, char whitelist
config = '--psm 8 --oem 3 -c tessedit_char_whitelist=ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789'
raw_text = pytesseract.image_to_string(plate_thresh, config=config)

# Clean: strip non-alphanumeric characters, uppercase
import re
cleaned_text = re.sub(r'[^A-Z0-9]', '', raw_text.upper())

Database Search (Hash Map + Linear Fallback)

python — search_vehicle_database()
# Strategy 1: Exact hash-map lookup — O(1) average
if plate_number in VEHICLE_DATABASE:
    return VEHICLE_DATABASE[plate_number], plate_number

# Strategy 2: Partial / Fuzzy Linear Search — O(n)
# Useful when OCR introduces 1–2 character errors
best_score = 0
for key in VEHICLE_DATABASE:
    score = sum(1 for a, b in zip(plate_number, key)
               if a == b)
    match_ratio = score / max(len(key), 1)

    if match_ratio >= 0.8 and score > best_score:
        best_score = score
        best_match = VEHICLE_DATABASE[key]
        best_key   = key

Time & Space Complexity Analysis

The table below summarises the algorithmic complexity of each stage in the LPR pipeline. W = image width in pixels, H = image height, d = bilateral filter diameter, n = number of contours / database entries.

Stage Algorithm Time Complexity Space Complexity Rating
Image Loading File I/O (disk read) O(W × H) O(W × H) Fast
Grayscale Conversion Weighted channel sum O(W × H) O(W × H) Fast
Bilateral Filtering Weighted kernel convolution O(W × H × d²) O(W × H) Moderate
Canny Edge Detection Gradient + Hysteresis O(W × H) O(W × H) Fast
Contour Extraction Suzuki-Abe boundary tracing O(W × H) O(n) Fast
Contour Sorting Timsort (Python built-in) O(n log n) O(n) Fast
Polygon Approximation Ramer–Douglas–Peucker O(n) per contour O(n) Fast
OCR (Tesseract) LSTM neural network O(n) chars O(model) Moderate
DB Exact Lookup Hash map (dict) O(1) average O(1) Optimal
DB Fuzzy Search Linear scan + similarity O(n × k) O(1) Linear
Total Pipeline All stages combined O(W × H × d²) O(W × H) Acceptable
ℹ️ The bilateral filter dominates the total complexity. For a 1920×1080 image with d=11, this means ~1920 × 1080 × 121 ≈ 251 million operations. In practice, OpenCV's optimised C++ implementation runs this in under 100ms on modern hardware.
Section 07

Vehicle Database Design

The database is implemented as a Python dictionary — a hash map data structure. The key is the normalised plate number (uppercase, no spaces), and the value is a nested dictionary with owner and type fields.

python — VEHICLE_DATABASE (hash map)
VEHICLE_DATABASE = {
    "KA01AB1234": {"owner": "Rajesh Kumar",  "type": "Car (Sedan)"},
    "KA02CD5678": {"owner": "Priya Sharma",  "type": "Motorcycle"},
    "MH12EF9012": {"owner": "Amit Patil",    "type": "Car (SUV)"},
    "DL8CAS3456": {"owner": "Sneha Verma",   "type": "Car (Hatchback)"},
    "TN09GH7890": {"owner": "Suresh Rajan",  "type": "Truck"},
    # ... 5 more entries
}

Why a Dictionary (Hash Map)?

A hash map was chosen because vehicle lookups are identity-based (exact key) and must be fast. With a hash map, retrieval time is constant (O(1)) regardless of database size, making it far superior to a list (O(n)) for this use case. This directly demonstrates the ADA concept of selecting the right data structure for the right problem.

Section 09

Advantages & Limitations

✓ Advantages

  • Fully automated — no human intervention required
  • Processes images in under a second on modern hardware
  • Works with standard Python + open-source libraries
  • Modular design — easy to extend with a real database
  • Demonstrates 5+ ADA concepts in a single project
  • Demo mode allows presentation without a real image
  • Hash-map search scales to millions of records at O(1)
  • Fuzzy search tolerates 1–2 OCR character errors

✗ Limitations

  • Accuracy depends on image quality and lighting
  • Tilted or partially occluded plates may be missed
  • Tesseract sometimes confuses '0'/'O' and '1'/'I'
  • Only rectangular plate shapes are detected
  • Database is in-memory — lost on program exit
  • Not suitable for real-time video without optimisation
  • Non-standard plate fonts reduce OCR accuracy
  • Multiple plates in one image may confuse detection
⚠️ Academic Note: This project is designed for demonstration and learning. Production LPR systems use deep-learning detectors (YOLO, SSD) and are trained on thousands of labelled plate images to achieve >95% accuracy across varying conditions.
